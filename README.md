# Медиум

Учебный сайт для иностранных студентов и студентов-мигрантов. В нём можно найти собеседника, задать вопрос об университете или попросить помощи с учёбой. Есть профили, чаты и рейтинг участников. Интерфейс работает на русском и английском.

[Открыть сайт](https://medium-bob01.amvera.io/) · [Макет в Figma](https://www.figma.com/design/78urA9a9EggvJYdgLotj5L/Untitled?node-id=0-1&t=x3YhCRRbUUCU5oZ9-1) · [Репозиторий](https://github.com/JustEd10/medium-student-community)

Интерфейс написан на React и Vite, сервер на Node.js и Express. Используются шрифты Inter и Manrope. Для запуска нужна Node.js 24.

Исправленная версия от 10.10.2026: [разбор изменений и сверка с заданием](docs/REVIEW-2026-10-10.md). [Публикация и проверка на хостинге](docs/DEPLOYMENT-2026-10-10.md).

## Демо и данные

На странице входа выбери Алину Ахметову в поле «Демо-пользователь» и нажми «Открыть демоверсию». Можно также зарегистрировать учебный аккаунт. Демо-профили и сообщения вымышлены.

Аккаунты, вопросы, помощь и чаты хранятся на сервере и общие для всех посетителей. Пароли хранятся только в виде хэша. Переключение RU/EN переводит интерфейс, а пользовательские тексты остаются на языке ввода.

## Запуск и публикация

Сайт и API работают в одном Node-процессе:

```bash
npm ci
npm run build
npm start
```

Порт задаётся переменной `PORT` (по умолчанию 3000). Данные пишутся в `DATA_DIR` (по умолчанию `server/storage`). Для разработки: `npm run server` и `npm run dev` в двух терминалах. `Dockerfile` и `amvera.yml` для хостинга лежат в корне проекта. [Загрузка через панель Amvera](deploy/amvera/README.md).

В Docker данные лежат в `/data`: при размещении подключи к этому каталогу постоянное хранилище и оставь одну реплику приложения. JSON-файл рассчитан на один Node-процесс. Перед обновлением сохрани копию существующего `db.json` и используй тот же `DATA_DIR`. Рабочие данные и токены в архив исходников не включены.

```bash
npm test
```

19 тестов проверяют правила, API, доступ к данным и сохранение. Тестовый сервер использует временный каталог; данные запущенного сайта не меняет.

## Серверная часть

Сервер написан на Node.js + Express, лежит в папке [server](server/). Данные заданий хранятся в обычных массивах в памяти, базы нет: после перезапуска всё возвращается к начальному состоянию. Сам сайт («Медиум») использует отдельные адреса `/api/app/*` и хранит данные в файле.

В проекте две сущности: `items` — вопросы студентов, `records` — ответы на них (в ответе хранится только `item_id`, название вопроса сервер подставляет сам).

Только сервер: `npm run server` (порт 3000, другой порт: `PORT=4000 npm run server`).

- http://localhost:3000/ — сайт (после `npm run build`)
- http://localhost:3000/app/ — страница с логином, вопросами, ответами и разделом «Мои записи»

Для React-версии (`npm run dev`) запросы на `/api` проксируются на сервер, его нужно запустить параллельно.

### Эндпоинты

| Метод | Адрес | Токен | Что делает |
| --- | --- | --- | --- |
| GET | `/` | нет | «Привет, это сервер моего сайта», пока сайт не собран; после `npm run build` здесь открывается сайт |
| GET | `/hello` | нет | то же приветствие, доступно всегда |
| GET | `/time` | нет | текущее время в JSON |
| GET | `/random` | нет | случайное число |
| GET | `/api/demo` | нет | захардкоженный массив из 3 элементов (на `/app/` его загружает кнопка «Загрузить демо-список») |
| POST | `/api/login` | нет | `{login, password}` → `{token}` |
| POST | `/api/logout` | да | убирает токен |
| GET | `/api/items` | нет | все вопросы, фильтры `?category=`, `?search=`, `?author=`, `?sort=answers` |
| GET | `/api/items/:id` | нет | один вопрос вместе с ответами |
| POST | `/api/items` | да | добавить вопрос `{title, body, category}` |
| DELETE | `/api/items/:id` | да | удалить вопрос (свой, админ — любой) вместе с ответами |
| GET | `/api/records` | нет | все ответы с названием вопроса, фильтры `?item_id=`, `?author=` |
| GET | `/api/records/my` | да | ответы текущего пользователя («Мои записи») |
| POST | `/api/records` | да | добавить ответ `{item_id, body}` |
| PATCH | `/api/records/:id/rating` | да | оценить ответ `{rating: 1..5}`, только автор вопроса |
| GET | `/api/rating` | нет | рейтинг участников по оценкам |

Токен передаётся в заголовке `Authorization: Bearer <токен>`.

### API основного сайта

Учебная страница `/app/` и основной сайт используют разные наборы данных и отдельные сессии. Это позволяет оставить массивы в памяти для задания и сохранять аккаунты и переписку основного сайта между перезапусками.

| Метод | Адрес | Что передать / получить |
| --- | --- | --- |
| GET | `/api/app/state` | `{me, state}`; гостю не возвращается личная переписка |
| POST | `/api/app/auth/register` | `{name, email, password}` → токен, пользователь и состояние |
| POST | `/api/app/auth/login` | `{email, password}` → токен, пользователь и состояние |
| POST | `/api/app/auth/demo` | `{id: "alina"}`; также доступны `wei` и `maria` |
| POST | `/api/app/auth/logout` | токен в заголовке; тело не требуется |
| POST | `/api/app/act` | токен и `{type, args}` → обновлённое состояние |

Действия: `addQuestion`, `addAnswer`, `rateAnswer`, `addHelp`, `offerHelp`, `completeHelp`, `rateHelp`, `openChat`, `sendMessage`, `saveProfile`. Пример тела запроса:

```json
{
  "type": "addQuestion",
  "args": {
    "title": "Где находится библиотека?",
    "body": "Хочу узнать часы работы.",
    "category": "Кампус"
  }
}
```

Сессии основного сайта действуют семь дней. При обновлении с прежней версии бессрочные токены не восстанавливаются: пользователям нужно войти заново. Аккаунты и записи сохраняются. Запись файла выполняется через временный файл; если сохранить не удалось, API возвращает 503 и сохраняет прежнее состояние в памяти. Повреждённый файл не заменяется демо-данными: сервер останавливается с сообщением об ошибке.

### Что считает и проверяет сервер

- заголовок вопроса 8–180 символов, текст до 2000, категория из списка (Документы, Учёба, Кампус, Языки, События);
- дату и автора вопроса или ответа сервер ставит сам, автор берётся из токена;
- у вопроса считается число ответов и длина текста;
- ответ 5–2000 символов, `item_id` должен существовать;
- оценить ответ может только автор вопроса и не свой ответ, оценка 1–5;
- чужой вопрос удалить нельзя (403), кроме админа.

### Примеры запросов

```bash
curl http://localhost:3000/hello
curl http://localhost:3000/time
curl http://localhost:3000/api/items
curl http://localhost:3000/api/items/1
curl -X POST http://localhost:3000/api/login -H "Content-Type: application/json" -d '{"login":"user","password":"qwerty"}'
curl -X POST http://localhost:3000/api/items -H "Authorization: Bearer ТОКЕН" -H "Content-Type: application/json" -d '{"title":"Где найти библиотеку?","body":"Нужен читательский билет","category":"Кампус"}'
curl -X POST http://localhost:3000/api/records -H "Authorization: Bearer ТОКЕН" -H "Content-Type: application/json" -d '{"item_id":1,"body":"Спроси в деканате"}'
curl http://localhost:3000/api/records/my -H "Authorization: Bearer ТОКЕН"
curl -X DELETE http://localhost:3000/api/items/4 -H "Authorization: Bearer ТОКЕН"
```

Коды ответов: 200/201 — успех, 400 — неверные данные, 401 — нет или неверный токен, 403 — нет прав, 404 — не найдено, 409 — почта занята, 413 — слишком большой запрос, 503 — не удалось сохранить данные.
