# API Медиума


Сервер написан на Node.js + Express, лежит в папке [server](../server/). Данные обоих API хранятся в SQLite. Основной сайт использует `/api/app/*`, учебное API — отдельные таблицы `lesson_*`. Записи и действующие сессии сохраняются после перезапуска. [Схема базы и проверка](database/README.md).

В проекте две сущности: `items` — вопросы студентов, `records` — ответы на них (в ответе хранится только `item_id`, название вопроса сервер подставляет сам).

[Запуск проекта](../README.md#запуск). Учебная страница находится по адресу `/app/`.

Токен передаётся в заголовке `Authorization: Bearer <токен>`.

### API основного сайта

Учебная страница `/app/` и основной сайт используют разные наборы данных и отдельные сессии. Данные обоих наборов сохраняются в SQLite между перезапусками.

| Метод | Адрес | Что передать / получить |
| --- | --- | --- |
| GET | `/api/app/state` | `{me, state}`; гостю не возвращается личная переписка |
| POST | `/api/app/auth/register` | `{name, email, password}` → токен, пользователь и состояние |
| POST | `/api/app/auth/login` | `{email, password}` → токен, пользователь и состояние |
| POST | `/api/app/auth/logout` | токен в заголовке; тело не требуется |
| POST | `/api/app/act` | токен и `{type, args}` → обновлённое состояние |

Действия: `addQuestion`, `addAnswer`, `rateAnswer`, `addHelp`, `offerHelp`, `completeHelp`, `rateHelp`, `openChat`, `sendMessage`, `markChatRead`, `saveProfile`, `deleteContent`, `restoreContent`, `setUserBan`, `withdrawHelp`, `setStudyHelpVisibility`. Пример тела запроса:

```json
{
  "type": "addQuestion",
  "args": {
    "title": "Где находится библиотека?",
    "body": "Хочу узнать часы работы.",
    "category": "Кампус"
  }
}
```

Сессии основного сайта действуют семь дней. При обновлении с прежней версии бессрочные токены не восстанавливаются: пользователям нужно войти заново. Аккаунты и записи сохраняются. Изменения фиксируются SQL-транзакцией. Если сохранить не удалось, API возвращает 503 и откатывает запись. Повреждённая база не заменяется демо-данными: сервер останавливается с сообщением об ошибке.

### Что считает и проверяет сервер

- заголовок вопроса 8–180 символов, текст до 2000, категория из списка (Документы, Учёба, Кампус, Языки, События);
- дату и автора вопроса или ответа сервер ставит сам, автор берётся из токена;
- у вопроса считается число ответов и длина текста;
- ответ 5–2000 символов, `item_id` должен существовать;
- оценить ответ может только автор вопроса и не свой ответ, оценка 1–5;
- чужой вопрос удалить нельзя (403), кроме админа.

### Примеры запросов

```bash
curl http://localhost:3000/hello
curl http://localhost:3000/time
curl http://localhost:3000/api/items
curl http://localhost:3000/api/items/1
curl -X POST http://localhost:3000/api/login -H "Content-Type: application/json" -d '{"login":"user","password":"qwerty"}'
curl -X POST http://localhost:3000/api/items -H "Authorization: Bearer ТОКЕН" -H "Content-Type: application/json" -d '{"title":"Где найти библиотеку?","body":"Нужен читательский билет","category":"Кампус"}'
curl -X POST http://localhost:3000/api/records -H "Authorization: Bearer ТОКЕН" -H "Content-Type: application/json" -d '{"item_id":1,"body":"Спроси в деканате"}'
curl http://localhost:3000/api/records/my -H "Authorization: Bearer ТОКЕН"
curl -X DELETE http://localhost:3000/api/items/4 -H "Authorization: Bearer ТОКЕН"
```

Коды ответов: 200/201 — успех, 400 — неверные данные, 401 — нет или неверный токен, 403 — нет прав, 404 — не найдено, 409 — почта занята, 413 — слишком большой запрос, 503 — не удалось сохранить данные.

В `sendMessage` передаются `chatId`, `body` и необязательный `clientId`. Повторная отправка с тем же идентификатором и текстом не создаёт дубликат. Сервер сохраняет новое сообщение с `readAt: null`; одна галочка появляется после подтверждения сохранения.

В `markChatRead` передаются `chatId` и `throughId` — идентификатор последнего просмотренного сообщения. Участник диалога может отметить только входящие сообщения до этой границы. Новые сообщения после неё остаются непрочитанными. Время `readAt` задаёт сервер и сохраняет в SQLite; у отправителя появляются две галочки. Клиент отправляет отметку, когда сообщения видны в открытой, активной вкладке. Переписка обновляется при возвращении во вкладку и раз в 6 секунд.


## Модерация и AI

`deleteContent({kind,id})` возвращает `undoExpiresAt`. Только удаливший запись пользователь может вызвать `restoreContent({kind,id})` в течение пяти секунд. Корзина в интерфейсе отсутствует; удалённые записи скрыты и не очищаются физически этой операцией.

Администратор вызывает `setUserBan({id,banned})`. Блокировка отзывает сессии и скрывает аккаунт с публикациями от обычных пользователей; амнистия сохраняет данные, после неё нужен новый вход. Администраторов блокировать нельзя.

`withdrawHelp({helpId})` снимает свой отклик на открытую заявку. `setStudyHelpVisibility({visible})` управляет видимостью предложения помощи в анкете; собственную заявку можно снять через `deleteContent` с kind `help`.

## Ответы основного сайта через JOIN

`GET /api/app/questions/:id/answers` возвращает доступные ответы с `authorName` и `questionTitle`. SQL соединяет `answers`, `questions` и `users`; закрытые поля и скрытые публикации не выдаются.
