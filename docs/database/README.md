# База данных Медиума

Приложение использует SQLite через встроенный модуль `node:sqlite` в Node.js 24. Сервер базы отдельно не запускается. Данные находятся в `DATA_DIR/medium.sqlite`; при работе рядом могут существовать `medium.sqlite-wal` и `medium.sqlite-shm`.

## Запуск отдельной локальной базы

```sh
npm ci
npm run build
DATA_DIR=/tmp/medium-sqlite-demo HOST=127.0.0.1 PORT=3000 npm start
```

На `http://127.0.0.1:3000` открывается основной сайт, на `/app/` — учебное REST API. Пустая установка не содержит аккаунтов основного сайта: их создают через регистрацию. Учебные пользователи из `server/data.js` вставляются в отдельные таблицы один раз. Их пароли в SQLite хешируются с индивидуальной солью; сессии ограничены сроком и отделены от сессий сайта.

## Схема

[Основная схема](../../server/migrations/001-initial.sql) и [схема учебного API](../../server/migrations/002-lesson.sql) создаются при первом запуске. Номер основной схемы хранится в `PRAGMA user_version`.

| Таблица | Данные и связи |
| --- | --- |
| `users` | Профиль, языки, интересы, навыки и хеш учётных данных; PK `id` |
| `questions` | Вопрос; FK `author_id → users.id` |
| `answers` | Ответ; FK `question_id → questions.id`, `author_id → users.id` |
| `help_requests` | Заявка; FK автора и выбранного помощника на `users.id` |
| `help_offers` | Отклики; FK заявки и пользователя; составной PK |
| `chats` | Диалог и его настройки |
| `chat_members` | Участники; FK на диалог и пользователя; уникальная позиция участника |
| `messages` | Сообщения; FK пары диалог и отправитель на участника диалога |
| `sessions` | Активные сессии сайта; FK на пользователя |
| `reports`, `ai_feedback`, `appeals` | Обращения; FK автора и проверяющего на пользователя |
| `moderation_log` | Журнал решений; FK действующего администратора |
| `metadata` | Версия состояния, настройки, отметки уведомлений, состояния AI и справочник |
| `lesson_users` | Отдельные пользователи учебного API |
| `lesson_items` | Учебные вопросы; FK автора на `lesson_users.id` |
| `lesson_records` | Учебные ответы; FK на вопрос и автора |
| `lesson_sessions` | Отдельные ограниченные по сроку учебные сессии |
| `lesson_meta` | Признак однократной загрузки учебных примеров |

Основные сущности разнесены по таблицам, связи представлены внешними ключами. Необязательные поля, например параметры AI и отметки удаления, сохраняются в `extras` своей записи. Списки языков и интересов — JSON-атрибуты профиля. Всё состояние не упаковано в один JSON-файл или одну строку таблицы.

Используются `STRICT`, `NOT NULL`, `CHECK`, первичные и внешние ключи. Проверка прикладных правил остаётся в `src/domain.js`. Бан и удаление профиля сохраняют нужные связи; публичное API скрывает соответствующие записи.

## Перенос из JSON

Первый запуск при отсутствии SQLite читает существующий `DATA_DIR/db.json`, проверяет данные, создаёт временную SQLite, переносит записи в транзакции и только после проверки публикует готовый файл. Исходный JSON не изменяется. Учётные записи, хеши, диалоги, сообщения, баны, настройки и действующие сессии сохраняются. Старые бессрочные и невалидные сессии отбрасываются.

Для отдельной локальной копии:

```sh
npm run db:migrate -- /absolute/path/to/local-data-copy
```

При наличии SQLite она считается источником данных, даже если пуста. Повторный запуск не импортирует старый JSON заново. Повреждение SQLite останавливает запуск; подстановка пустой базы не выполняется. Команда миграции без существующего JSON или SQLite отказывается работать.

## API и JOIN

Примеры CRUD и реальных запросов: [01-crud.sql](01-crud.sql), [02-queries.sql](02-queries.sql), [документация API](../API.md).

```sh
curl http://127.0.0.1:3000/api/items
curl 'http://127.0.0.1:3000/api/records?item_id=1'
curl http://127.0.0.1:3000/api/app/questions/QUESTION_ID/answers
```

`GET /api/records` делает JOIN ответа, вопроса и автора и возвращает `item_title` и `author` вместе с ответом. Учебная страница использует эти готовые данные. `GET /api/app/questions/:id/answers` возвращает имя автора и заголовок вопроса через JOIN основного сайта. Закрытые данные не включаются; скрытые публикации недоступны.

API читает SQLite перед обработкой запросов. Объекты состояния используются как совместимый слой для существующих правил продукта. Прикладное изменение фиксируется SQL-транзакцией; память обновляется только после успешного COMMIT. Эта реализация переписывает набор строк основного состояния при изменении; она рассчитана на текущий небольшой проект и один процесс записи. Для большого объёма следующим шагом будут точечные SQL-изменения вместо полной записи состояния.

## Транзакции

Запись основного состояния: `BEGIN IMMEDIATE → запись таблиц → COMMIT`. Ошибка на любом шаге вызывает `ROLLBACK`. Создание сессии и пользователя фиксируется вместе с состоянием. Удаление учебного вопроса и его ответов выполняется в одной транзакции. Тест вставляет временные триггеры, которые ломают второй шаг, и проверяет, что первый шаг тоже отменён. Публичной команды для намеренной поломки сервера нет.

## Индексы

Индексы покрывают ответы по вопросу и автору, заявки и отклики, участников и сообщения диалогов, срок сессии и фильтры учебного API. Для сравнения:

```sh
npm run db:benchmark
```

Скрипт создаёт отдельную временную базу с 10 000 ответами и выполняет один запрос с индексом `answers_question` и без него. Выводит медиану серий после прогрева и оба `EXPLAIN QUERY PLAN`: `SCAN answers` и `SEARCH ... USING COVERING INDEX`. Временная база удаляется; рабочая не используется. Результат зависит от компьютера и не равен времени ответа HTTP.

## Резервная копия и восстановление

[Полная инструкция](../backups.md). Логическая копия содержит все данные сайта и учебные таблицы. Обе группы сессий исключаются. Копия совместима с шифрованием и загрузкой в Google Drive; ключи провайдеров и конфигурация Диска в неё не включаются.

```sh
DATA_DIR=/tmp/medium-sqlite-demo node scripts/backup.mjs create
node scripts/backup.mjs check /absolute/path/to/snapshot.json
node scripts/backup.mjs rehearse /absolute/path/to/snapshot.json /tmp/new-medium-restore
```

Восстановление допускается только в новый каталог. Полученная SQLite проверяется чтением данных и внешних ключей. Для проверки запуска укажите новый `DATA_DIR`. После восстановления нужен повторный вход. Старые JSON-снимки также поддерживаются.

## Проверка и материалы для сдачи

```sh
npm test
npm run db:verify
```

`db:verify` запускает настоящий локальный сервер на свободном порту с отдельной временной базой. Проверяет регистрацию, вопросы, ответы, JOIN, изменение, права, перезапуск, откат, удаление и восстановление, затем измеряет индекс. Создаёт `test-results/database/report.html`, журнал запросов без паролей и токенов и результат измерения. Временная база удаляется. Внешние AI API и рабочий сайт не используются.

[Коллекция Postman](Medium-SQLite.postman_collection.json) содержит подготовленные запросы и проверки. Импортируйте её и используйте только локальный адрес отдельной демонстрационной базы. После запроса 06 остановите Runner, перезапустите сервер и выполните 07; затем удалите свои тестовые записи шагами 08–09. Запуск в Postman и его скриншоты выполняются отдельно; автоматический отчёт не выдаётся за Postman.
