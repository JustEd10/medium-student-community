# Развёртывание в Amvera

Сайт: [medium-bob01.amvera.io](https://medium-bob01.amvera.io/).

Сайт работает в приложении `medium`, аккаунте `bob01`, регионе `msk0`. Для публикации через Safari в раздел Code загружены `Dockerfile` и `source.tar.gz`, затем запущена сборка. Создан бесплатный внешний HTTPS-домен. Дополнительные реплики и тариф не менялись.

Docker собирает React/Vite на Node.js 24 и отдаёт только `dist/` через Nginx на порту 80. Последний загруженный архив соответствует проверенному коммиту `bbc2929a60e2005348d2ac2ad7ae8c699fde406c`. Все 34 файла архива совпадают с его исходниками. SHA-256 архива: `805abad259b31c42af4acbdbe94445e6119c2128db0248705b4b0f41f3122e9c`. В [GitHub Actions](https://github.com/JustEd10/medium-student-community/actions/runs/37687775820) прошли 7 тестов логики и 33 браузерных теста production-сборки в Chromium, Firefox и WebKit.

Архив загружен через Safari в коммит Amvera `ddea5a3fd02f6ec4a26748d5c7c4e3b423a0f898`. Сохранённая конфигурация Docker использует `amvera.yml` и порт 80. После сборки подтверждены статус «Запущено» и 1 из 1 реплик. HTML и 16 файлов — JavaScript, CSS, фон, два логотипа и 11 SVG-иконок — совпадают с локальной production-сборкой и возвращают HTTP 200. На опубликованной версии проверены центр навигации, волна в шапке, белая надпись «Опубликовать», «Топ-5», текст главной и одинаковые выпадающие фильтры на ПК и при ширине 390 пикселей. Результат записан в `deployment-check.json`.

## Повторная публикация через Safari

Подготовь рядом с репозиторием папку с двумя файлами:

```sh
mkdir -p ../medium-amvera-upload
cp deploy/amvera/Dockerfile ../medium-amvera-upload/Dockerfile
git archive --format=tar.gz --output=../medium-amvera-upload/source.tar.gz HEAD src public index.html package.json package-lock.json vite.config.js postcss.config.js tailwind.config.js
```

В Amvera открой «Репозиторий», вкладку Code и нажми «Загрузить данные». При первой публикации загрузи оба файла; для обновления исходников достаточно `source.tar.gz`. Затем открой «Конфигурация» и нажми «Собрать». Если конфигурационного файла нет, сначала сохрани окружение `docker`, инструмент `docker`, Dockerfile `Dockerfile` и порт 80 кнопкой «Применить». Архив должен называться `source.tar.gz`: Docker распакует его при сборке. Дождись статуса «Запущено» и проверь внешний HTTPS-адрес.

Чтобы опубликовать изменения из GitHub, снова упакуй исходники и загрузи их через Safari. Автоматическая синхронизация с GitHub пока не подключена.

Профили, сообщения, вопросы и оценки сохраняются в браузере посетителя. Для хранения данных на сервере и переписки между устройствами нужна серверная часть.
