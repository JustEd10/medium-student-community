# AI-помощник РЭУ

В разделе «Вопрос-ответ» можно спросить AI отдельно или включить автоматический ответ при публикации. Автоматический ответ хранится в вопросе отдельно от ответов студентов, не участвует в рейтинге и исчезает при удалении вопроса. Текст вопроса передаётся в GigaChat; переписка и учётные данные пользователей не передаются. Публичные поля профилей отдельно проверяются модератором, как описано ниже.

RAG ищет подходящие выдержки в `server/knowledge/reu.json` по словам и их нормализованным формам, затем передаёт выбранные фрагменты модели. Это локальный текстовый индекс без отдельной векторной базы. База покрывает расписание, учётную запись, электронные сервисы, общежития, социальную поддержку, обзор информации для иностранных студентов и контакты военно-учётного стола. Это не полный архив документов университета. Основные источники проверены 11.10.2026; контакты ВУС и кабинет отдела социальной работы — 12.10.2026. Их нужно обновлять при изменениях. Если подходящих фрагментов нет, запрос модели не выполняется. Ссылки берутся из базы, а не из ответа модели.

## Серверная настройка

Ключ хранится только в переменной `GIGACHAT_AUTH_KEY` либо в закрытом файле `${DATA_DIR}/gigachat-config.json` с правами 600. Поля файла: `authKey`, необязательные `scope`, `model`, `caFile`. Не помещать этот файл в Git, сборку, публичные каталоги или раздел Amvera «Код». В Amvera использовать закрытый постоянный каталог «Данные».

По умолчанию: scope `GIGACHAT_API_PERS`, модель `GigaChat-3-Lightning`. Переменные `GIGACHAT_SCOPE`, `GIGACHAT_MODEL`, `GIGACHAT_CA_FILE` переопределяют настройки. Корневой сертификат из официальной инструкции Сбера хранится в `server/certificates`; он применяется только к запросам GigaChat вместе со стандартными корнями Node. Глобальные настройки доверия не меняются, проверка TLS не отключается.

OAuth: `https://ngw.devices.sberbank.ru:9443/api/v2/oauth`; генерация: `https://api.giga.chat/v1/chat/completions`. Токен кешируется до истечения срока. Ответы помощника ограничены пятью попытками за пять минут на пользователя. Общая очередь выполняет один запрос GigaChat на процесс: модерация имеет приоритет, внутри каждой группы сохраняется порядок поступления. Уже выполняющийся запрос не прерывается. Для JSON-хранилища предусмотрена одна реплика приложения. Ошибка AI не отменяет публикацию вопроса. После перезапуска незавершённый ответ можно запросить повторно.

В очереди могут ожидать до 50 запросов; для модерации зарезервированы 10 мест, поэтому ответы помощника занимают не более 40 мест. Ожидание до запуска ограничено двумя минутами. Переполнение возвращает `AI_QUEUE_FULL`, истечение ожидания — `AI_QUEUE_TIMEOUT`; просроченные запросы не отправляются провайдеру. Перед отправкой сервер повторно проверяет актуальность контента и доступ аккаунта. Очередь находится в памяти процесса; она не повышает квоты провайдера и не повторяет запросы автоматически. При постоянном потоке модерации ответы могут истечь по времени ожидания.

## API

- `GET /api/app/assistant/status`: готовность настройки, без секретов.
- `POST /api/app/assistant` с `question`: отдельный ответ, нужна активная сессия.
- `POST /api/app/assistant` с `questionId`: ответ для своего вопроса или вопроса, модерируемого администратором. Готовый ответ повторно возвращается без расхода токенов, если он подготовлен с текущей версией базы и правил проверки. Устаревший ответ пересчитывается по нажатию пользователя; массового автоматического пересчёта нет.
- `addQuestion` принимает `autoAI` (boolean, по умолчанию true).

[Авторизация GigaChat](https://developers.sber.ru/docs/ru/gigachat/api/reference/rest/gigachat-api), [сертификаты](https://developers.sber.ru/docs/ru/gigachat/certificates), [источники РЭУ](https://www.rea.ru/studentu).

## AI-модератор: только отметки

После регистрации, публикации вопроса, ответа, заявки на учебную помощь и изменения профиля сервер ставит проверку публичных полей в очередь GigaChat. Передаются только имя, фамилия, направление, курс, языки, интересы, навыки, описание профиля либо заголовок, текст и категория публикации. Email, login, credential, сессии и личные сообщения не входят в запрос. Перед публикацией интерфейс раскрывает передачу публичного текста GigaChat.

Ответ принимается только как строгий JSON с boolean `flagged` и массивом фиксированных категорий: harassment, hate, threats, sexual, spam, personal_data. Некорректный ответ означает ошибку проверки, а не нарушение. Причины формируются сервером из категорий. AI никогда не скрывает и не удаляет публикации, не блокирует аккаунты. Отметка — рекомендация для администратора, а не доказанное нарушение.

`state.aiReviews` сохраняется атомарно вместе с контентом; только администратор получает его через API. Статусы: pending, clean, flagged, error, dismissed. Действия `/api/app/act`: `dismissAIReview` и `retryAIReview` с `args.key` (ключ из aiReviews); сервер проверяет активную административную роль. Повтор разрешён только после ошибки, снятие — для отметки или ошибки. Изменённый текст получает новую проверку. Хэш публичных полей защищает от применения устаревшего результата; одинаковый текст и прочие действия не создают повторных проверок. Удалённые записи исключаются.

Обработчик модерации подаёт в общую очередь до двух проверок и пополняет её после завершения каждой; транспорт выполняет только одну генерацию одновременно. Ошибки модели не отменяют публикацию. После перезапуска pending становится error и требует явного повтора администратором; автоматических бесконечных повторов нет. При ошибке сохранения результата повтор приостанавливается до перезапуска. Старые записи не проверяются массово при старте, только после изменения публичных полей. Проверки используют тот же закрытый конфиг GigaChat; отдельный ключ не нужен. Для тестов подставляется локальная функция completion без запросов провайдеру.

## Проверенные кабинеты и качество ответов

Сокращение ВУС (вуса, вусе, вусу, вусом) нормализуется в «военно-учётный стол». Общие слова «кабинет», «отдел», «этаж» и «корпус» исключены из тематического поиска, чтобы кабинет одного отдела не попадал в ответ о другом.

Для места приёма используются записи `office` с названиями подразделения и проверенным ответом, без генерации номера моделью. ВУС и Военный учебный центр различаются. Кабинет ВУС 100 добавлен по уточнению владельца проекта от 12.10.2026. Корпус не уточнён. Официальная страница подтверждает `vus@rea.ru`, но не номер кабинета; эта разница явно показана в ответе и подписи источника. Для отдела социальной работы подтверждены третий корпус, третий этаж и кабинет 343. При неизвестном или неоднозначном подразделении помощник просит уточнение.

В ответах модели проверяются числовые значения: новые числа, которых нет в выбранных выдержках, не показываются; ссылки вида [1] не считаются фактическими числами. Сгенерированные номера кабинетов также не показываются. Эта проверка не доказывает правильность всех утверждений: число может относиться к другой сущности, а сроки могут быть написаны словами. Она дополняет справочник и тематический поиск, а не заменяет обновление источников и оценку качества на реальных вопросах.

Для смены модели сначала сравнивают доступные модели на одинаковых вопросах и источниках: корректность фактов, отказ при нехватке данных, ссылки, время и расход токенов. Параметр `GIGACHAT_MODEL` уже поддерживается; фактическая доступность проверяется для конкретного API-аккаунта. Эта доработка не переключает модель и не меняет конфигурацию рабочего сайта.

## Расширенный справочник и сравнение моделей

12.10.2026 база расширена до десяти тематических записей. Добавлены сектор записи читателей НИБЦ (кабинет 301, шестой корпус), отдел стран Европы, Америки, Африки и Ближнего Востока (кабинет 649, третий корпус) и Военный учебный центр. Кабинет конкретного международного отдела не переносится на все подразделения управления. Для ВУЦ указан контакт VUC@rea.ru; номер кабинета не придуман.

Источник уточнения хранится в `sourceNote`, передаётся в контекст модели и показывается под ссылкой. ВУС 100 не обозначается как факт с официального сайта. После обновления версии базы автор или администратор может снова нажать «Спросить AI» у готового ответа: старый кэш пересчитывается, актуальный используется повторно.

`node scripts/compare-ai.mjs --output /private/tmp/medium-ai-offline.json` проверяет сценарии без внешних запросов. Ответы, для которых нужна модель, помечаются LIVE_MODEL_NOT_RUN. Это не сравнение качества моделей.

После настройки закрытого `DATA_DIR` вне репозитория можно явно запустить `node scripts/compare-ai.mjs --live --output /private/tmp/medium-ai-live.json`. Команда проверяет доступность настроенной модели и GigaChat-2-Pro через `/models`, выполняет одинаковые девять вопросов последовательно и ограничивает генерации двадцатью запросами. При ошибке прекращает вопросы для этой модели, автоматических повторов нет. Рабочая конфигурация сайта не меняется. В отчёте сохраняются источник, результат, время, фактически возвращённая модель и total_tokens, если провайдер их сообщил. Секреты не выводятся.

Ответы из справочника отмечаются generated=false: их нельзя засчитывать как качество конкретной модели. Автоматические проверки ожидаемых слов и источников — только первичные фильтры, не доказательство семантической точности. Перед выбором модели нужна ручная оценка фактов и отказов по отчёту. В этой доработке выполнены offline-проверки и, после разрешения владельца, реальное сравнение: 12 генераций на двух моделях. [Результаты](AI-COMPARISON.md). Смена модели на рабочем сайте не выполнялась. Флаг `--extra-only` запускает три дополнительные темы вместо базовых девяти сценариев.

## Выбор адресата вопроса

В разделе «Вопрос-ответ» по умолчанию выбран вариант «Спросить студентов». Форма публикует вопрос для сообщества; дополнительный AI-ответ выключен по умолчанию в интерфейсе. Пользователь может включить его отдельно. Серверный default `autoAI=true` сохранён для совместимости; форма явно передаёт выбранное значение.

«Спросить AI» открывает отдельную форму справочника РЭУ без публикации. Для бытовых советов интерфейс рекомендует студентов. Кнопка «Задать этот вопрос студентам» переносит текст в черновик публичной формы, но не публикует его. Длинный текст сохраняется в заголовке и подробностях; при превышении 2000 символов подробностей нужна правка перед публикацией. Переключение адресата сохраняет черновики.

Проверены в локальном браузере переключение, перенос вопроса о шаурме, отсутствие автоматической публикации, выключенный autoAI и фокус поля после переноса. Макет просмотрен при ширинах 1440 и 390 px; на телефоне горизонтального переполнения нет.
